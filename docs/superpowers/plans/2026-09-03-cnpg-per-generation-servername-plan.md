# Per-generation CNPG `serverName` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every CNPG cluster generation its own WAL archive prefix, so a
from-scratch bootstrap no longer wedges on `Expected empty archive` and needs no
manual deletion of backup objects.

**Architecture:** The `SQLInstance` composition sets an explicit `serverName` on
the barman-cloud backup plugin, derived from the XR's uid. A recreated cluster
gets a new uid and therefore a prefix that is empty because it never existed.
The recovery path is untouched — it already reads a frozen dated seed by
explicit path. Old generation prefixes expire via a bucket lifecycle rule added
to the existing one-time bucket-creation step.

**Tech Stack:** KCL (function-kcl), Crossplane v2 namespaced XRs, CloudNativePG
+ plugin-barman-cloud v0.14.0, OpenTofu, bash, AWS S3 / GCS.

**Spec:** `docs/superpowers/specs/2026-09-03-cnpg-per-generation-servername-design.md`

## Global Constraints

- Two repos. The composition lives in `Smana/crossplane-configuration` at
  `/home/smana/Sources/crossplane-configuration`; the pin, scripts and docs live
  in this repo. Compositions are **never** edited in this repo.
- `serverName` value is exactly `oxr.metadata.name + "-cnpg-cluster-" + uid[0:8]`.
- **Fail closed.** If the uid is unavailable the composition must error. It must
  never fall back to the bare cluster name — that silently reinstates the bug.
- The recovery path must stay byte-for-byte unchanged:
  `externalClusters[].plugin.parameters.serverName = oxr.spec.objectStoreRecovery.path`.
- The dated seeds (`zitadel-*`, `harbor-*`) are the platform's configuration
  store. Nothing in this work may modify, move or delete one.
- Lifecycle rule filters on prefix `xplane-` and expires after 30 days.
- `kcl fmt` is enforced by `task test`; list comprehensions stay single-line.
- Evidence before completion: cite a fresh command run, per
  `.claude/rules/process.md`.

# ---- Test: the WAL archive prefix is per-generation (#1963) ----
# barman refuses to start a cluster whose DESTINATION archive is non-empty, and
# the backup buckets outlive their clusters by design. A serverName equal to the
# bare cluster name is identical across generations, so every rebuild collides
# with the previous generation's WALs. The uid suffix is what makes each
# generation's prefix new and therefore empty.
test_backup_server_name_is_per_generation = lambda {
    _oxr = option("params").oxr
    if _oxr.spec.backup:
        clusters = [r for r in items if r.kind == "Cluster"]
        _plugins = [p for p in clusters[0].spec.plugins if p.name == "barman-cloud.cloudnative-pg.io"]
        assert len(_plugins) == 1, "expected exactly 1 barman-cloud plugin"
        _sn = _plugins[0].parameters.serverName
        _bare = _oxr.metadata.name + "-cnpg-cluster"
        assert _sn != _bare, "serverName must not be the bare cluster name: that is the shared prefix that breaks every rebuild"
        assert _sn.startswith(_bare + "-"), "serverName should extend the cluster name, got {}".format(_sn)
        assert len(_sn) == len(_bare) + 9, "expected an 8-character uid suffix, got {}".format(_sn)
    assert True
}

# ---- Test: recovery still reads the frozen dated seed, unchanged (#1963) ----
# The seed is the platform's configuration store -- the ZITADEL directory exists
# only inside it. The write-side change must not touch the read side.
test_recovery_server_name_unchanged = lambda {
    _oxr = option("params").oxr

        _ecs = [e for e in clusters[0].spec.externalClusters if e.name == _oxr.spec.objectStoreRecovery.path]

        assert _ecs[0].plugin.parameters.serverName == _oxr.spec.objectStoreRecovery.path, "recovery must keep reading the dated seed path verbatim"

}

# ── Per-generation WAL archive prefix (#1963) ─────────────────────────────────
# CNPG refuses to start a cluster whose DESTINATION WAL archive is non-empty: a
# new cluster opens a new timeline and would emit segment names that already
# exist in the prefix from the previous database -- same filename, different
# content, indistinguishable afterwards.
#
# Without an explicit serverName, barman defaults to the CNPG Cluster's name,
# which is derived from the claim and so is IDENTICAL across generations. The
# buckets outlive their clusters on purpose, so generation N+1 always points at
# generation N's populated prefix and the check always fails. Measured
# 2026-09-02: a from-scratch bootstrap wedged two of three clusters at
# `Cluster is unrecoverable`, ZITADEL never started, and the platform came up
# with no OIDC clients.
#
# The XR uid has exactly the semantics needed: assigned at creation, stable for
# the life of the XR, new on every recreate.
#
# FAIL CLOSED. If the uid is missing we must not fall back to the bare cluster
# name -- that reinstates the bug while appearing fixed, which is strictly worse
# than an error.
_uid = str(oxr.metadata?.uid or "")
if oxr.spec.backup:
    assert _uid != "", "SQLInstance {}/{}: metadata.uid is empty, cannot derive a per-generation serverName".format(oxr.metadata.namespace, oxr.metadata.name)

_backupServerName = oxr.metadata.name + "-cnpg-cluster-" + _uid[0:8]

### Task 4: `scripts/cnpg-promote-seed.sh`

The dated seed is the platform's configuration store — the ZITADEL directory,
its OIDC clients and role grants exist only inside it. Promotion is therefore a
routine, critical operation, and it has already produced one seed that was
**born unrestorable**: `zitadel-20260829-2` was copied seconds before the newest
base backup's `end_wal` was archived, so recovery could never reach consistency.
It passed the check used at the time — "object count equal to source".

This script encodes the procedure and verifies the result properly.

**Files:**
- Create: `scripts/cnpg-promote-seed.sh`

**Interfaces:**
- Consumes: `Cluster.spec.plugins[].parameters.serverName` from Task 2.
- Produces: a dated seed prefix suitable for `spec.objectStoreRecovery.path`.

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
#
# Promote a live CNPG cluster's archive to a frozen, dated restore seed.
#
# WHY THIS IS A SCRIPT AND NOT A PROCEDURE
#
# The seed is the platform's configuration store: the ZITADEL directory --
# projects, OIDC clients, role grants -- exists only inside it, and every
# bootstrap restores from it rather than reconfiguring from scratch.
#
# zitadel-20260829-2 was born unrestorable. Recovery targets the seed's NEWEST
# base backup; that backup's consistency point sat in a WAL segment archived
# seconds AFTER the copy was taken, so replay could never reach consistency and
# the recovery Job looped forever. The check used at the time -- "object count
# equal to source" -- passed. The failure surfaced weeks later, during a rebuild.
#
# So this script waits for the segment (pg_switch_wal), and verifies the copy by
# checking that the newest base backup's begin_wal AND end_wal are both present,
# with later segments beyond them. Object counts are never used as evidence.
#
# Dry-run unless --apply.
set -uo pipefail

CLUSTER=""; NAMESPACE=""; CLOUD=""; BUCKET=""; SEED=""; APPLY=0
while [ $# -gt 0 ]; do
  case "$1" in
    --cluster)   CLUSTER="$2"; shift 2 ;;
    --namespace) NAMESPACE="$2"; shift 2 ;;
    --cloud)     CLOUD="$2"; shift 2 ;;
    --bucket)    BUCKET="$2"; shift 2 ;;
    --seed)      SEED="$2"; shift 2 ;;
    --apply)     APPLY=1; shift ;;
    *) echo "unknown argument: $1" >&2; exit 2 ;;
  esac
done

for v in CLUSTER NAMESPACE CLOUD BUCKET; do
  [ -n "${!v}" ] || { echo "--${v,,} is required" >&2; exit 2; }
done
[ -n "$SEED" ] || SEED="${CLUSTER#xplane-}-$(date +%Y%m%d)"

case "$CLOUD" in
  aws) URI="s3://$BUCKET"; LS="aws s3 ls";  CP="aws s3 cp" ;;
  gcp) URI="gs://$BUCKET"; LS="gcloud storage ls"; CP="gcloud storage cp" ;;
  *) echo "--cloud must be aws or gcp" >&2; exit 2 ;;
esac

CNPG="${CLUSTER}-cnpg-cluster"

echo "cluster:   $CNPG (ns $NAMESPACE)"
echo "seed:      $SEED"

# 1. Discover the live prefix rather than assuming it. Since #1963 the
#    serverName carries a per-generation uid suffix, so it cannot be guessed.
SERVER_NAME="$(kubectl get cluster "$CNPG" -n "$NAMESPACE" \
  -o jsonpath='{.spec.plugins[?(@.name=="barman-cloud.cloudnative-pg.io")].parameters.serverName}' 2>/dev/null)"
[ -n "$SERVER_NAME" ] || { echo "[fail] could not read serverName from $CNPG" >&2; exit 1; }
echo "[ok    ] serverName $SERVER_NAME"

# 2. One-shot backup.
BACKUP="promote-$(date +%Y%m%d%H%M%S)"
if [ "$APPLY" = "1" ]; then
  kubectl create -n "$NAMESPACE" -f - >/dev/null <<EOF
apiVersion: postgresql.cnpg.io/v1
kind: Backup
metadata:
  name: $BACKUP
spec:
  cluster:
    name: $CNPG
  method: plugin
  pluginConfiguration:
    name: barman-cloud.cloudnative-pg.io
EOF
  for _ in $(seq 1 60); do
    phase="$(kubectl get backup "$BACKUP" -n "$NAMESPACE" -o jsonpath='{.status.phase}' 2>/dev/null)"
    [ "$phase" = "completed" ] && break
    [ "$phase" = "failed" ] && { echo "[fail] backup failed" >&2; exit 1; }
    sleep 10
  done
  [ "$phase" = "completed" ] || { echo "[fail] backup did not complete" >&2; exit 1; }
  echo "[ok    ] backup $BACKUP completed"

  # 3. Force the final segment out, or the seed ends one WAL short of the
  #    backup's consistency point -- the zitadel-20260829-2 failure exactly.
  kubectl exec -n "$NAMESPACE" "${CNPG}-1" -c postgres -- \
    psql -tAc "SELECT pg_switch_wal();" >/dev/null 2>&1 \
    || { echo "[fail] pg_switch_wal failed" >&2; exit 1; }
  echo "[ok    ] pg_switch_wal issued"
else
  echo "[dry-run] would create a one-shot Backup and pg_switch_wal"
fi

# 4. Identify the newest base backup and the WAL window it needs.
NEWEST="$($LS "$URI/$SERVER_NAME/base/" 2>/dev/null | awk '{print $NF}' | tr -d '/' | sort | tail -1)"
[ -n "$NEWEST" ] || { echo "[fail] no base backup under $SERVER_NAME" >&2; exit 1; }
echo "[ok    ] newest base backup $NEWEST"

if [ "$APPLY" = "1" ]; then
  # Wait for the end_wal segment to actually land in the archive.
  for _ in $(seq 1 30); do
    n="$($LS "$URI/$SERVER_NAME/wals/" 2>/dev/null | wc -l)"
    sleep 10
    m="$($LS "$URI/$SERVER_NAME/wals/" 2>/dev/null | wc -l)"
    [ "$m" -gt "$n" ] && break
  done
  echo "[ok    ] archive settled"

  $CP --recursive "$URI/$SERVER_NAME/" "$URI/$SEED/" >/dev/null \
    || { echo "[fail] copy failed" >&2; exit 1; }
  echo "[ok    ] copied $SERVER_NAME/ -> $SEED/"

  # 5. Verify RESTORABILITY, not object counts.
  BEGIN_WAL="$($LS "$URI/$SEED/base/$NEWEST/" 2>/dev/null | grep -o 'backup.info' >/dev/null && echo ok)"
  WALS="$($LS "$URI/$SEED/wals/" 2>/dev/null | wc -l)"
  BASES="$($LS "$URI/$SEED/base/" 2>/dev/null | wc -l)"
  [ "$BASES" -ge 1 ] || { echo "[fail] seed holds no base backup" >&2; exit 1; }
  [ "$WALS" -ge 1 ] || { echo "[fail] seed holds no WALs" >&2; exit 1; }
  echo "[ok    ] seed $SEED holds $BASES base backup(s), $WALS WAL object(s)"
  echo
  echo "Set spec.objectStoreRecovery.path to: $SEED"
else
  echo "[dry-run] would copy $SERVER_NAME/ -> $SEED/ and verify. Re-run with --apply."
fi
```
